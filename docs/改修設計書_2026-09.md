# オノマトペ学習支援システム 改修設計書（2026-09）

対象：項目2〜6（項目7「独自性の整理」は今回対象外）

---

## 0. 改修の核になる考え方

現行システムは「カテゴリー → 結びつく表現形式」を**対応表（`category_expression`）で直接持っている**ため、
正誤は出せるが「**なぜ**その形になるのか」を機械的に説明できない。解説文はすべて人手で書いた固定文だった。

そこで本改修では、**前接条件を素性の集合として構造化**し、
判定もフィードバックも「素性の照合」から**自動生成**する方式に変える。

```
オノマトペ ──[素性]──→ 継続性 / 動作性 / 意志性
                            ↓ 照合
表現形式   ──[前接条件]──→ 許容する素性値の集合
                            ↓
                   ○結びつく / ×結びつかない
                   ＋「どの素性が足りないか」を名指しした説明
```

これが項目5（フィードバック設計）の土台であり、同時に項目2・3・4・6すべての改善に効く。

## 1. データ構造の変更

### 1-1. `expressions` テーブル（前接条件の構造化）

追加カラム：

| カラム | 内容 | 例 |
|---|---|---|
| `req_cont` | 許容する継続性（`\|`区切り、空＝不問） | `＋` / `＋\|変化結果の＋` / 空 |
| `req_act` | 許容する動作性 | `高` / `中\|高` / 空 |
| `req_vol` | 許容する意志性 | `＋` / `ー\|関与しない` / 空 |
| `req_label` | 学習者向けの条件表示 | `＋継続性／動作性（中・高）` |
| `why_cont` | その継続性が必要な理由 | 「開始したあと状態が続くことが前提なので…」 |
| `why_act` | その動作性が必要な理由 | 「具体的で見える動きの継続を表すので…」 |
| `why_vol` | その意志性が必要な理由 | 「自分の意志で始める意味なので…」 |
| `ok_example` | ○の例 | `○きょろきょろしつづける` |
| `ng_example` | ×の例 | `×いらいらしつづける` |
| `form_base` / `form_past` | Step4 選択肢用の活用形 | `しつづける` / `しつづけた` |

**設定値（10形式）**

| 表現形式 | req_cont | req_act | req_vol |
|---|---|---|---|
| するところだ | － | 高 | ＋ |
| しようとする | － | 高 | ＋ |
| しはじめる | ＋ | 中・高 | － |
| しだす | ＋ | 中・高 | ー・関与しない |
| してくる | ＋ | 中 | － |
| していく | ＋ | 低 | ー |
| しつづける | ＋ | 高 | － |
| しているところだ | ＋・変化結果の＋ | － | － |
| したところだ | 変化結果の＋ | 中 | － |
| してしまう | － | － | － |

（「－」＝不問）

> **整合性の担保**：この条件集合から8カテゴリー×10形式の○×を計算し、
> 現行の `CATEGORY_EXPRESSIONS`（研究資料由来の正解表）と**全80セルが一致することを
> `init_db.py` 内で assert する**。一致しなければDBを作らずエラーで止める。
> 以後、条件を触るたびに研究資料との整合が自動検証される。

### 1-2. `categories` テーブル（素性の根拠）

`why_cont` / `why_act` / `why_vol` を追加。
Step2・素性ドリルで「なぜその素性値になるのか」を出すための、カテゴリー単位の根拠文。

### 1-3. `phon_forms` テーブル（音韻形態→素性の予測）

`pred_cont` / `pred_act` / `pred_note` を追加。

| 形 | 予測継続性 | 予測動作性 | 備考 |
|---|---|---|---|
| 2モーラ反復形 | ＋ | —（語による） | 動作性は語の意味しだい。§9参照 |
| 2モーラ反復形の変種 | ＋ | 高 | 乱れた動き |
| 「っ＋り」型 | 変化結果の＋ | 中 | 低動作の状態を表す例外あり（ぐったり・ゆっくり） |
| 「ん＋り」型 | ＋ | 低 | — |
| 「っ」で終わる型 | ー | 高 | 変化結果型の例外あり（ほっ） |

これにより、**予測と実際の素性が食い違う語を自動検出**して
「この語は音の形からの予測どおり／例外です」というコメントを出せる（項目3）。

### 1-4. `practice` テーブル（Step4 の例文：方式変更）

**旧**：カテゴリー共通テンプレート `{ctx}、だんだん{word}[ ？ ]。` ＋ 手書き選択肢
→ 「手が、だんだんべたべた…」のような不自然な連結が発生。

**新**：語ごとに完成した自然文を持つ。

| カラム | 内容 |
|---|---|
| `word_id` | 語（39語 × 2問 = 78問） |
| `frame` | オノマトペと接続の「と」まで入った完成文。空所は `[ ？ ]` |
| `correct_key` | 正解の表現形式キー |
| `form` | 使う活用形（`base` / `past`） |

例：`試験が終わって、ほっと[ ？ ]。` ＋ `correct_key=shitatokoroda` / `form=past`
→ 「試験が終わって、ほっとしたところだ。」

**誤答選択肢は保持しない。** 実行時に、その語のカテゴリーと**結びつかない**表現形式から
ランダムに2つ選び、指定の活用形で提示する。したがって

- 誤答は必ず「素性条件を満たさない形」になる（＝素性で説明できる）
- 解説文は素性照合から自動生成できる
- 出題するたび選択肢が変わる

**素性に集中する場と、文法形式に集中する場を分離する**。

### 2-1. 素性ドリル（項目2）— 素性のみを判断する4タイプ

| タイプ | 問い | ねらい |
|---|---|---|
| **A 単一素性判定** | 「『ぐったり』の動作性は？」（場面つき） | 素性値そのものの判断 |
| **B 音韻形態からの予測** | 「『っ』で終わる型の語は、継続性がどうなりやすい？」 | 音の形と素性の関係づけ（項目3と連動） |
| **C 同素性さがし** | 「『びっくり』と同じ継続性を持つのはどれ？」 | 語をまたいで素性を抽象化する |
| **D 素性→カテゴリー逆引き** | 「〈＋継続性・動作性（中）・ー意志性〉の感情語はどれ？」 | 素性の組み合わせからの逆方向の思考 |

文法形式は一切出さない。A・C・Dは語の場面文つきで出題し、ヒントには
継続性の図／動作性の段階／意志性の判定基準／その語の音韻形態を出す。

### 2-2. 前接条件ドリル

| タイプ | 問い |
|---|---|
| **E 前接条件を答える** | 「『〜しだす』が必要とする素性は？」 |
| **F 結びつく語を選ぶ** | 「『〜するところだ』と結びつくのはどれ？」（4語から選択） |

Fの解説は素性照合の自動生成文を使う。

## 5. フィードバックの設計（項目5）

### 5-1. 判定関数

```python
expr_check(category, expression)
  → ok:bool, checks:[{素性名, 許容値, 実際の値, ok}]
```

条件が空の素性はチェック対象にしない（＝「不問」は判定に出さない）。

### 5-2. 生成される文

**○結びつく場合**

> 「きょろきょろ」の素性は〈継続性＋・動作性（高）・意志性 関与しない〉。
> 「〜しつづける」が求めるのは〈＋継続性・動作性（高）〉。
> 継続性＋＝○、動作性（高）＝○ → **すべて満たすので結びつく**。

**×結びつかない場合（足りない素性を名指しする）**

> 「〜しつづける」は動作性が〈高〉のオノマトペを求めますが、
> 「いらいら」の動作性は〈中〉です。
> ＝「〜しつづける」は具体的で見える動きの継続を表すため、
> 感情・感覚（中）では使えません。
> → **だから結びつきません**（×いらいらしつづける）。

満たさない素性が複数あるときは、すべて列挙する。

### 5-3. 適用箇所

| 画面 | フィードバック |
|---|---|
| Step2 結果 | 素性ごとに、カテゴリーの根拠文＋音韻形態からの予測との一致／例外コメント |
| Step3 結果 | 表現ごとに上記の自動生成文（結び忘れ／余分に結んだを区別） |
| Step4 結果 | 正解＝満たす条件の説明、誤答＝足りない素性の名指し |
| 素性ドリル結果 | タイプ別（素性の根拠／音韻形態の予測／同素性の判断） |
| 前接条件ドリル結果 | 前接条件の意味＋素性照合 |

**方針**：どの画面でも「正誤」で終わらせず、必ず
**「どの素性が」「どうだから」「だからこの形になる／ならない」**の3点を出す。

## 9. 追補：フェーズ1を「知識＋演習」の段階制にする

### 背景

当初は「知識ページ（/phase1）で全部読む → 素性ドリル（/phase1/drill）で解く」構成だった。
しかしこれは両側から成立しない。

- 知識ページを通して読むだけでは、学習者にとって意味のある活動になりにくい
- かといっていきなりドリルに入ると、判断の根拠を持たないので解けない

そこで **知識と演習を1段階ずつ融合**し、「説明 → その場で3問 → 素性にもとづく解説」を
積み上げる形に変える。説明は問題を解いている間も同じ画面に残す。

### 5段階

| 段階 | 学ぶこと | 出題 |
|---|---|---|
| 1 | 継続性（図3つ＋見分け方） | その語の継続性を答える ×3 |
| 2 | 動作性（3段階＋継続性との連動） | その語の動作性を答える ×3 |
| 3 | 意志性（＋／ー／関与しない、「今から〜しよう」テスト） | その語の意志性を答える ×3 |
| 4 | 音韻形態からの予測と、その限界 | 形→素性の予測 ×2 ＋ **予測が外れる語** ×1 |
| 5 | 素性の組み合わせ → 8カテゴリー | 同素性さがし ×1 ＋ カテゴリー逆引き ×2 |

出題の作り方：

- 段階1〜3は、3問の答えが**2種類以上の素性値になる**ように語を選ぶ（同じ答えの連続を避ける）
- 段階4の3問目は `EXCEPTION_WORDS`（音韻形態からの予測と実際の素性が食い違う語）から出す。
  予測をそのまま当てはめると間違える問題を意図的に置き、「予測は出発点、最後は意味で決める」ことを学ばせる

### 音韻形態の予測値の修正

2モーラ反復形（ABAB）の動作性を「中」と予測していたが、実際には
きょろきょろ＝高／いらいら＝中／ごろごろ＝低 と語によって割れ、例外が12語出て対応表が機能しなかった。
そこで **`pred_act` を空（＝「—（語による）」）** に変更した。

- 空の予測は対応表で「—（語による）」と表示し、例外としてカウントしない
- 空の予測は出題対象から除外する（答えの決まらない問題を出さない）
- フィードバックでは「この形からは動作性を予測できません」と明示する

結果、例外欄は ぎくしゃく（動作性）／ゆっくり・ぐったり（継続性・動作性）／ほっ（継続性・動作性）だけになり、
「予測が効くところ」と「効かないところ」の区別が学習内容として成立するようになった。

### 既存2ページの扱い

- 旧・知識ページは `/phase1/summary`「素性のまとめ（復習用）」として残す（各段階の結果画面からリンク）
- 旧・素性ドリルは `/phase1/drill`「総合ドリル」として残し、5段階を終えたあとの仕上げに位置づける

### 検証（verify_routes.py に追加）

- 5段階すべてが200を返し、各段階がちょうど3問であること
- 段階1〜3に**その段階の素性以外の問題が混ざらない**こと
- 正解を入力すれば全問正解になること
- 段階1〜3で、20回出題して毎回**答えが2種類以上**になること
- 予測できない素性（反復形の動作性）が出題されないこと

## 10. 追補2：段階を「学習ページ → 練習ページ」に分け、学習側を厚くする

### 背景

§9で段階制にしたが、1ページ内に説明と問題が同居していたため、
スクロールで説明が飛ばされ、結局「問題とヒントだけを見る」形になりやすかった。
また説明が知識の羅列で、**初めて学ぶ人が自分で判断にたどり着く道筋**がなかった。

そこで各段階を2ページに分け、学習側に「考え方をなぞる仕掛け」を3つ入れる。

```
/phase1/stage/{n}            学習ページ（1/2）
    ① 説明（従来の知識）
    ② 判断手順チェックリスト     ← 新
    ③ 対比ペア                  ← 新
    ④ 思考ガイド（段階的に開く例題） ← 新
        ↓「練習に進む」
/phase1/stage/{n}/practice   練習ページ（2/2）＝3問
        ↓
/phase1/stage/{n}/practice/check  解説
```

練習ページは学習ページを通ってからしか到達しない導線にした。総合ドリルは従来どおり最後。

### ② 判断手順チェックリスト（`stage_guides`）

「語を見ていきなり決める」のではなく、**順に問いを立てれば答えに着く**手順を段階ごとに提示する。
例（継続性）：

1. 場面を思い浮かべる
2. 「今もまだ続いているか？」と聞く → はい ＝ ＋継続性
3. 続いていないなら「変化の結果は残っているか？」と聞く → 残る ＝ 変化結果の＋ ／ 残らない ＝ ー継続性

同じ手順は**練習ページでも折りたたみで開ける**ので、手順を思い出しながら解ける。

### ③ 対比ペア（`contrast_pairs`）

値の分かれ目は、近い語を並べたときにいちばんよく見える。段階ごとに3組。

| 段階 | 例 | 分かれ目 |
|---|---|---|
| 継続性 | いらいら ／ いらっ | 続くか一瞬か |
| 動作性 | きょろきょろ ／ いらいら | 外から見える動きがあるか |
| 意志性 | ぶらぶら ／ おろおろ | ＋意志性 か 関与しない か |
| 音の形 | びっくり ／ ゆっくり | 同じ「っ＋り」型でも予測が外れる |
| カテゴリー | いらいら ／ にこにこ | 素性は同一、種類だけが違う |

`feature` を指定したペアはその素性だけを対比表示、空のペアは3素性＋種類をまとめて表示する。

### ④ 思考ガイド（`worked_examples` / `worked_steps`）

**採点しない例題**。語と場面を見せ、「まず自分で答えを決めてから」と促したうえで、
ボタンで手順を1つずつ開き、最後に結論を出す。段階ごとに1題。

例（継続性・がっかり）：場面を思い浮かべる → 変化は続いている？ → 結果は残っている？ → 変化結果の＋

段階4は予測が外れる語（ゆっくり）、段階2も例外語（ぐったり）を選び、
「形からの予測より意味が優先」という判断そのものをなぞらせる。

### 検証（verify_routes.py に追加）

- 5段階の学習ページに、判断手順・対比ペア・思考ガイド・練習への導線がすべてあること
- **学習ページに回答フォームが混ざっていないこと**（説明と練習が再び同居しないこと）
- 対比ペアが実際に対比になっていること（単一素性の対比なら値が異なる／全素性の対比なら値または種類が異なる）
- 思考ガイドが3手順以上あり、結論を持つこと
- 練習ページが3問で、正解を入力すれば全問正解になること

> 実際、この検証が「段階5のいらいら／にこにこは素性が同じ」を検出した。
> これは意図した対比（違うのは種類）だったため、判定条件を種類込みに修正した。
